# 内置 `edit` 的崩溃恢复与幂等重试

**状态：已在当前工作树实现，已通过 Windows 本地恢复、并发和双端入口测试。** 对应 [Issue #29](https://github.com/SSK988I/Coding-agent/issues/29)。适用于终端和桌面共用的本地 Python 运行时。验收对象是持久会话中对单个普通文件的一次 `edit` 调用，包含该调用中的全部替换。

## 用户遇到的问题

用户让 Agent 把 `a = 1` 改成 `a = 10`。文件写成功后，桌面进程在会话保存工具结果之前退出。下次打开会话时，用户看到“结果未知”。直接重发相同的替换，`a = 10` 中仍能匹配 `a = 1`，最终会得到 `a = 100`。

变更前，`edit` 持有按真实路径分配的进程内锁，计算完整新内容后以 `w` 模式打开原文件。进程在截断和写完之间退出，也可能留下空文件或部分内容。工具结果在回合结束时另行追加到会话。历史修复函数只给缺少结果的调用生成 `uncertain`，无法从聊天记录判断文件是否写过。[编辑实现](../../packages/core/src/agent_core/tools/edit.py) · [写入锁](../../packages/core/src/agent_core/tools/_mutation.py) · [会话事件持久化](../../packages/core/src/agent_core/agent.py) · [缺失结果处理](../../packages/core/src/agent_core/session/messages.py)

## 从中断处继续

查看历史只读。打开会话、切换分支或查看工具卡片均不会修改项目文件。用户继续原会话时，运行时核对当前分支上缺少确定结果的 `edit`。终端和桌面在原调用位置显示同一结论。

| 已有证据 | 运行时和用户可见行为 |
| --- | --- |
| 已保存完成结果 | 直接显示原结果和 diff。文件后来被修改、移动或删除，也只说明那次编辑已完成。 |
| 已保存写入意图，目标路径仍有效，字节与预期新版本一致 | 补记完成，显示“已核对文件并补回编辑结果”。不重新执行替换，不改变文件修改时间。 |
| 已保存写入意图，目标仍是记录中的原文件和原版本 | 显示“编辑尚待完成”，提供针对**这一次调用**的“重试原编辑”。仅在用户选择后，通过当前权限检查并重新核对文件，才可写入。 |
| 目标已删除、链接改指其他路径；或目标字节不是预期新版本，且不能确认仍为原版本 | 显示冲突和目标路径，保留现有文件。用户可查看当前内容，重新发起一次编辑。 |
| 缺少可信记录、记录损坏，或当前权限不足以核对目标 | 保留 `uncertain` 并说明原因。两端均不根据相同参数、相似文本或聊天摘要猜测结果。 |

“重试原编辑”绑定原工具卡片，在终端交互界面和桌面均可触发。它不会重发整轮提示或重跑同一批次的其他工具。已归档、只读会话只显示记录。Plan 或当前审批策略禁止写入时，重试显示禁止原因，待恢复记录仍可在条件满足后处理。[访问权限](desktop-permissions.md) · [Plan 模式](plan-mode.md)

## 操作身份与记录

一次逻辑编辑由 **来源会话 ID、原助手消息的持久化条目 ID、该消息内的 `tool_call_id`** 唯一标识。原调用必须能唯一定位。运行时负责生成和绑定这个组合键。模型仍使用已有的 `edit` 工具参数，例如将整个调用表示为：

```json
{"type":"toolCall","id":"call_edit_1","name":"edit","arguments":{"path":"example.py","edits":[{"oldText":"a = 1","newText":"a = 10"}]}}
```

模型提供 `path` 和 `edits`。规范输入中 `path` 为非空字符串，`edits` 为非空数组，每项必填字符串 `oldText` 和 `newText`，均不接受 `null`。`oldText` 非空，`newText` 可以是空字符串，表示删除匹配内容。各项在同一原文件上匹配且互不重叠。工作目录、会话范围、操作身份、权限、文件版本均从运行时获得。[工具定义与匹配规则](../../packages/core/src/agent_core/tools/edit.py)

同一身份只能绑定一份参数。按原调用的工作目录和规范化后的参数计算摘要，保留 `edits` 顺序和文本原值。同一身份提交不同参数时，在读取或写入目标前拒绝，并保留原记录。同样的参数出现在新的助手调用中，按新操作执行。分叉会话可读取复制的历史结果，父会话的待完成写入只可在来源会话处理。

设计采用 Python 标准库 SQLite，在会话数据目录、对应 JSONL 旁按会话保存操作记录。组合键有唯一约束。首次获准执行的编辑才创建记录库。目录权限沿用私有会话数据的要求，备份会话时一起保存旁文件。此记录包含原编辑片段和 diff，按会话数据管理。

| 记录内容 | 用途 |
| --- | --- |
| 身份、记录格式版本、规范化参数及其摘要、原始工作目录 | 定位原调用，拒绝同 ID 异参，重建本次替换。 |
| 调用路径、解析后的目标路径、原文件标识与版本信息 | 在恢复时识别删除、同名换文件、符号链接改指及已观察到的外部改动。 |
| 修改前、预期修改后的 SHA-256 | 均以磁盘实际字节计算，包含 BOM 和换行符。用于区分原版本、预期新版本和其他内容。 |
| 状态及工具结果 | `prepared` 表示意图已提交，文件可能已替换，记录中保存预期成功摘要及 `details.patch`。`completed` 保存可回放的成功结果。恢复时确认冲突则持久标记 `conflicted`，保存原因并结束该操作，后续编辑需发起新调用。 |

纯内存会话（如 `--no-session`）使用相同的原子替换和路径互斥，在进程内去重，退出后无记录可供恢复。旧会话可以继续产生新的受保护编辑；旧调用没有对应记录时沿用 `uncertain`。

## 一次写入的提交顺序

1. 通过现有工具准入、Plan 和审批检查。对持久会话，确认含该调用的原助手消息已经可靠落盘。取得操作身份后先查询已有记录，参数不符即拒绝，已完成则返回缓存结果。
2. 获取目标真实路径对应的跨进程锁，在锁内重新读取记录、解析路径及核对版本。终端、桌面的 `edit` 和 `write` 共用同一锁命名空间。不同会话的记录库彼此独立，因此锁位置按本机用户与规范目标路径确定。进程退出后由操作系统释放锁。
3. 按现有规则一次计算全部替换，生成最终字节、摘要和 unified diff。持久提交 `prepared` 后才能改动目标。原消息或准备记录保存失败时，停止执行并保持原文件完整。
4. 在**目标文件所在目录**创建独占临时文件，写完最终字节并刷盘，保留原文件权限，再次核对路径和原版本。通过后用同文件系统的原子替换提交。对符号链接编辑其已核对的真实目标，保留链接本身。对多硬链接或无法保留原访问权限的目标，在替换前报告原因，避免拆开链接或放宽权限。临时文件仅由创建它的操作清理。进程在替换前被强制终止时，目标目录可能留有以 `.coding-agent-edit-` 开头的暂存文件；恢复流程根据原目标与操作记录判定结果。
5. 在释放路径锁前持久提交 `completed` 和工具结果，再通过现有流程保存会话结果。进入替换阶段后，若无法确定替换是否成功，或无法提交完成记录，报告 `uncertain` 并保留 `prepared`。此处若写入确定的 `failed`，会掩盖可能已经成功的编辑。原结果已确认时，历史存储失败只需补回结果。

恢复 `prepared` 时也持有同一把锁。先核对链接和解析路径，再比较字节。原子替换本身会改变文件标识，因此同一目标路径已有预期新字节就可补记成功，无需推断最后写入者。仅当内容等于原字节时，才用平台文件标识、大小及高精度修改时间确认仍是原版本。证据不足时禁止重写。重试重建的最终字节也必须与记录的预期哈希一致，运行时升级造成计算结果不同时保留现场。

路径锁保护遵循协议的 Agent 进程。外部编辑器可在最后一次版本检查与原子替换之间写入。普通文件系统上的检查加替换无法消除这个窗口；验收分别验证 Agent 间互斥和已发生外部修改的冲突检测。首版保证针对进程中断，整机断电及网络文件系统故障不在此保证内。

## 会话结果与错误

会话 JSONL 和文件替换无法作为一次事务提交。正常路径照常保存 `toolResult`。恢复时以操作记录持久补记完成状态，并由共享会话层把缺失的结果放回**原助手消息的原调用位置**，供模型、终端工具卡和桌面变更视图读取。已有确定的会话结果优先。同一调用始终呈现一份结果，不向当前分支末尾追加一条无归属的历史消息。切分支、压缩历史、归档或多次打开会话都不能触发文件重写。

成功沿用 `status=completed`、原 `content` 和 `details.patch`。桌面只把已确认成功的 patch 计入本轮已执行变更。待恢复和冲突卡片如展示请求中的 `edits`，标为“计划修改”。冲突和重试建议放在第一条可读文本中，便于终端直接展示。下表约定恢复相关状态及 `details.code`。通用参数校验、普通匹配失败及审批拒绝沿用现有工具规则。重试尝试遭拒不会覆盖原调用已经确认的结果。[工具结果状态](long-task-runtime.md) · [工具结果类型](../../packages/core/src/agent_core/types.py)

| 条件 | 状态及错误码 | 后续行为 |
| --- | --- | --- |
| 同一操作身份携带不同参数 | `failed` / `EDIT_OPERATION_MISMATCH` | 拒绝这次提交。原调用仍可按原参数查询。 |
| 核对确认目标已变更 | `failed` / `EDIT_CONFLICT` | 保留现场，提示重新读取并发起新编辑。 |
| 原消息或准备记录保存失败，确认目标尚未写入 | `failed` / `EDIT_PREPARE_FAILED` | 告知用户文件尚未修改。该次尝试结束，存储恢复后可发起新调用。没有持久意图可供原地恢复。 |
| 已有可信意图，尚待重试或补记 | `uncertain` / `EDIT_RECOVERY_PENDING` | 文本说明待核对阶段。仅在确认原版本且具备写入条件时提供原操作重试入口。 |
| 记录损坏或核对所需证据不可读 | `uncertain` / `EDIT_RECOVERY_UNAVAILABLE` | 说明当前无法判断，提示恢复可读性后再核对。旧调用从未有记录时沿用已有 `uncertain` 表示。 |

以下是上述调用成功和恢复冲突时的工具返回示例，采用 `AgentToolResult` 的字段。`content` 为非空文本块数组，`type` 为 `text`、`text` 为字符串。成功的 `details` 含字符串 `patch`，上述恢复错误的 `details` 含表中的字符串 `code`。`terminate` 为布尔值。这些结果由现有运行时封装为 `toolResult` 消息并关联到 `call_edit_1`。

```json
{"status":"completed","content":[{"type":"text","text":"Successfully replaced 1 block(s) in example.py."}],"details":{"patch":"--- example.py\n+++ example.py\n@@ -1 +1 @@\n-a = 1\n+a = 10"},"terminate":false}
```

```json
{"status":"failed","content":[{"type":"text","text":"example.py 在中断后已被修改，已保留当前内容。请重新读取文件后发起新编辑。"}],"details":{"code":"EDIT_CONFLICT"},"terminate":false}
```

## 验收

以临时项目及独立会话目录运行。故障注入要在独立 Python 子进程中强制退出，再由新进程打开同一会话，避免正常异常清理或内存缓存掩盖中断。下表列出验收标准。

| 场景 | 必须观察到的结果 |
| --- | --- |
| 准备记录写入失败，或在 `prepared` 提交后、替换前退出 | 前者磁盘仍为原文件，不能显示成功。后者首次恢复可识别原版本，显式重试后得到一次预期修改。临时文件未写完时原目标也完整。 |
| 替换后、`completed` 提交前退出 | 以 `a = 1` → `a = 10` 为例，连续恢复两次仍为 `a = 10`，文件修改时间不变，历史只有一个成功结果，diff 与首次计算一致。 |
| `completed` 后、JSONL 写结果前退出 | 即使用户随后改过文件也回放原结果，两端历史与模型上下文均只有一份工具结果，保留用户改动。 |
| 重复提交 | 同 ID 同参数返回已有结果。同 ID 异参拒绝且不碰文件。不同原调用即使参数一致也拥有各自身份。 |
| 已准备操作遇到外部改动 | 分别覆盖第三种内容、删除、同名换成字节相同的原版文件、符号链接改指。保留现场并给出冲突原因。同一目标路径被用户手动改为预期新内容时只补记结果。 |
| 多进程、同一路径 | 终端与桌面并发恢复同一操作，实际替换至多一次。两个独立会话并发 `edit` / `write` 时按路径串行化，后取得锁的操作读取最新状态。 |
| 兼容性与权限 | 覆盖 BOM、CRLF、多段编辑、权限及符号链接。旧会话缺记录仍为 `uncertain`。纯内存会话无持久操作库。只查看历史、切换分支或打开 fork 均不重放原编辑。权限收紧后重试不能写文件。 |

完成条件是终端和桌面通过共享运行时得到相同文件内容、相同的操作结论，以及同一份关联到原调用的差异。

## 使用与验证

桌面在原编辑卡片上提供核对和重试操作。终端在同一张卡片上显示带来源条目和工具调用 ID 的 `/check-edits` 或 `/retry-edit` 命令。核对只检查目标。确认仍是原版本后，可按当前权限重试。会话分叉时只复制已经确认的结果。

Windows 上以独立进程验证了替换前后强制退出、双进程重试只替换一次、保留用户后续修改、跨工作目录审批以及分支恢复。Linux/macOS 的文件权限与锁行为还需要在相应系统上运行用例。[崩溃与恢复测试](../../packages/app/tests/test_edit_crash_recovery.py) · [双端入口测试](../../packages/app/tests/test_edit_recovery_surfaces.py) · [原子写入测试](../../packages/core/tests/test_edit_atomicity.py)
