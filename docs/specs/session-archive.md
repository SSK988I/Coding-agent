# 桌面会话归档

侧栏会话行在悬停或键盘聚焦时显示归档图标。点击后，会话从普通列表移入“已归档”。侧栏标题旁的归档图标打开归档列表，返回按钮切回普通列表；归档列表中的恢复图标可将会话放回普通列表。

归档当前会话时保留聊天视图，输入框停用，并显示“恢复会话”入口。打开其他已归档会话也只显示历史；恢复成功后可继续对话。归档、恢复与列表刷新都有等待或失败反馈，失败不提前移除列表项。新建会话返回普通列表。

归档会话的侧边对话仍可查看已有记录，新建、输入、发送和批准操作停用；停止和拒绝操作保留。

## 存储与边界

- 归档状态属于整个会话，与活动分支及 Plan 状态无关。旧会话默认未归档，也兼容读取 JSONL header 的可选 `archived` 字段。
- 归档状态通过会话旁的独立小型元数据文件原子保存，不重写聊天 JSONL，避免覆盖其他 CLI 进程同时追加的消息。元数据文件名取会话文件名转小写后的稳定散列，在各操作系统上一致；兼容读取早期按原始大小写生成的元数据，新文件优先。复制或备份会话时需保留同目录归档元数据。
- 会话路径、ID、父会话、历史消息、工具结果和活动分支均保留。归档不会删除附件或回滚项目文件、Git 操作及其他副作用。
- 普通列表和自动恢复最近会话跳过已归档记录。已归档记录仍可按 ID 打开；桌面后端在恢复前拒绝发消息、执行计划、压缩或启动子代理。
- 已打开会话在读取快照、发起任务及归档或恢复前重新读取持久化归档状态，避免另一窗口改变状态后使用过期缓存；这不会重载历史或改变活动分支。元数据损坏时拒绝继续修改，不默认视为未归档。
- 运行、压缩、子代理或侧边对话尚未结束时，拒绝改变归档状态。保存失败时，内存中的归档状态也不推进。
- 归档接口只接受当前工作区内的会话 ID。切换工作区重置归档列表；迟到的列表响应不能覆盖新工作区或当前筛选结果。

## 桌面接口

| 接口 | 行为 |
| --- | --- |
| `session.list` | 默认返回普通会话；`{archived: true}` 只返回归档会话 |
| `session.archive({sessionId})` | 保存归档状态，返回 `{sessionId, archived: true}` |
| `session.unarchive({sessionId})` | 保存恢复状态，返回 `{sessionId, archived: false}` |
| workspace / `session.snapshot` | 包含当前会话的 `archived` 状态 |
| `session.archived` / `session.unarchived` | 通知前端刷新列表及当前会话的归档状态 |

不增加数据库、依赖或常驻后台任务，也不移动会话文件。
